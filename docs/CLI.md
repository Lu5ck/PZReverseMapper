# PZ Reverse Mapper command line

Command-line converter for compiled Project Zomboid map cells.

The converter ships in the same jar as Studio: run
`java -jar PZReverseMapper-<version>.jar` with any arguments to use it
(with no arguments, the jar opens Studio). `--gui` opens Studio explicitly.

It reads `.lotheader` and `world_X_Y.lotpack` files, supports old `300x300`
cells and new POT/v42 `256x256` cells, then writes TMX cells plus a `.pzw`
WorldEd project. Build 42 maps stay on their native `256x256` grid.

If an `objects.lua` file is present in the input folder, objects are parsed and
written back into the `.pzw` cells on the target grid. Rectangle
objects, polygons, polylines, line width, and arbitrary object properties are
preserved.

PNG preview images are generated by default. Per-cell `base`, `full`, and
`vegetation` images are written under `maps_img/`, then merged into `Map.png`,
`Map_veg.png`, and `world.png`. `Map.png` is the base terrain image used by the
world workflow and does not draw RoomDefs visually. When zombie density data is
available, the converter also writes `Map_ZombieSpawnMap.png`.

For unfiltered Build 42 exports, if the input folder contains
`maps/biomemap_X_Y.png` tiles, the converter assembles them into a complete
`biomemap.png`. Filtered `--cells` test exports skip this global biomemap to
keep small validation runs lightweight.

Use `--extract-tiles` to extract Project Zomboid `.pack` assets from the
`--tiles` path. Raw atlas images are written to
`TilesRaw/<physical-pack>/`, restored individual tiles to
`TilesSingle/<logical-pack>/<tileset>/`, and reconstructed
WorldEd/TileZed sheets to `Tiles/<pack>/`. Each tile is first restored on its
real canvas using the atlas rectangle, offset, original name, and
`tileWidth`/`tileHeight` stored in the `.pack`. Sheets always contain eight
columns, making their pixel width exactly `8 * tileWidth`.

Files ending in `.floor.pack` are part of the matching normal pack, but their
raw atlas directories remain separate. For example,
`TilesRaw/Tiles2x.floor.pack` and `TilesRaw/Tiles2x.pack` are distinct, while
their cut floor and non-floor tiles are combined under the logical
`TilesSingle/Tiles2x.pack` directory before tilesets are rebuilt. This can
produce many images, so it is best run once per game build or tiles update.

For modded maps, keep `--tiles` pointed at the vanilla Project Zomboid `media`
folder and add `--mod-tiles` for a separate prepared asset folder. That folder
can contain `.tiles` files plus a `texturepacks/` or `texturespack/` subfolder
with the required `.pack` files. It is loaded after the vanilla media folder, so
modded sheets can be added or override matching tileset metadata without copying
anything into the game install.

Every compiled building is written as a BuildingEd TBX file under
`tbx_buildings/`. With `--tbx-config <folder>` (the BuildingEd config folder of
PZ_Mapping_Tools, holding `BuildingTiles.txt`, `BuildingFurniture.txt` and
`TMXConfig.txt`), each one is rebuilt as a real BuildingEd building: rooms,
walls, trims, floors, ceilings, grime, doors, windows, curtains, shutters,
stairs and furniture, chosen by majority vote against the config and checked by
re-rendering with BuildingEd's layout rules. Tiles that cannot be reproduced
stay as user-drawn tiles. Use `--tiles` too, so the grime and window rules can
read the game's tile properties. Without `--tbx-config`, each TBX holds the
building's rooms and keeps its tiles as user-drawn tiles.

Buildings whose TBX comes out identical share one file, named after the first
room and the building size (`hall_3x7.tbx`, `hall_3x7_2.tbx`, ...).
`tbx_buildings/buildings.csv` lists every compiled building with its TBX file,
world position (`world_x`, `world_y`, `world_z`), source cell, source building
id and the TMX cell it was placed in (`lot_cell`, empty when not placed).

Each building is placed back on its TMX cell as a WorldEd lot: an object named
`lot` whose type is `../tbx_buildings/<file>.tbx`, in a `Lots` object group on
the building's level (`<level>_Lots` in classic 1.0 TMX files). The tiles the
lot draws and the building's rooms are left out of the TMX layers and RoomDefs,
so WorldEd does not stack them twice when it generates lots; ground and
vegetation stay in the TMX. A building that does not fit in one TMX cell, or
whose TBX would draw tiles that are not in the compiled map, is not placed: its
tiles and RoomDefs stay in the TMX. The TMX tiles plus the tiles the lots draw
are always exactly the compiled tiles.

Use `--no-building-tbx` to skip building TBX files and lots; the TMX then keeps
every tile and every RoomDef. Use `--tbx-only` when you only want the building
TBX files. In that mode the converter still reads the compiled tiles and rooms,
but skips `.tmx`, `.pzw`, preview images, and `objects.lua` writing (and places
no lots). `--no-room-tbx` is still accepted for old scripts but has no effect:
RoomDef TBX files are no longer written.

Ground filler and vegetation (`blends_natural_01_*`, trees, foliage, plants and
grass overlays) under the building's outside squares stay in the TMX.

## Usage

```bash
java -jar PZReverseMapper-1.0.0.jar \
  --input "D:\Path\To\CompiledMap" \
  --output "D:\Path\To\Export" \
  --tiles "D:\Path\To\ProjectZomboid\media" \
  --mod-tiles "D:\Path\To\PreparedModAssets" \
  --name "MyMap" \
  --source-cell-size 256 \
  --tbx-config "D:\Path\To\PZ_Mapping_Tools" \
  --cells 46_26,46_27 \
  --clean
```

TBX-only inspection export:

```bash
java -jar PZReverseMapper-1.0.0.jar \
  --input "D:\Path\To\CompiledMap" \
  --output "D:\Path\To\TBX_Only" \
  --source-cell-size 256 \
  --tbx-config "D:\Path\To\PZ_Mapping_Tools" \
  --cells 46_26 \
  --tbx-only \
  --clean
```

Tilesheet extraction can be enabled on any normal export:

```bash
java -jar PZReverseMapper-1.0.0.jar \
  --input "D:\Path\To\CompiledMap" \
  --output "D:\Path\To\Export" \
  --tiles "D:\Path\To\ProjectZomboid\media" \
  --extract-tiles \
  --clean
```

In PowerShell, end continued lines with a backtick (`` ` ``) instead of `\`.

`--tiles` is optional. When omitted, the converter infers tilesets from tile
names with an `8`-column fallback.

`--mod-tiles` is optional. It points to a separate mod asset root and is ignored
when omitted. The CLI also accepts `--mod-media` as an alias.

`--cells` is optional. It is useful for validating a small set of source cells
without converting an entire map folder.

`--clean` is guarded. If the output folder already contains files, the CLI asks
you to type `CLEAN` before continuing, then moves existing output contents to
the Recycle Bin (Windows) or Trash (macOS, Linux; the freedesktop.org Trash is
used when no desktop integration is available). Nothing is ever deleted
permanently: if no trash is available, the clean is refused. It refuses
protected locations such as Desktop, Documents, Downloads, the home folder,
and drive roots.

`--source-cell-size` is optional. When it is set, the converter validates the
detected `.lotheader` source cell size before exporting. Use `300` for v41 and
older maps, or `256` for Build 42 POT maps.

`--no-images` is optional. Use it when you want the map/project export without
the PNG preview images.

`--extract-tiles` is optional. It reads packs from `--tiles` and, when present,
from `--mod-tiles`. The tilesheet images are reconstructed from `.pack`
metadata and do not require a `.tiles` file. `--tiles` can point at the Project
Zomboid `media` folder, a folder containing `.pack`/`.tiles` files, or a single
`.pack` file.

`--tiles-only` performs only this pack extraction. It requires an output and at
least one tiles path, but no compiled-map input, and does not read lotheaders or
lotpacks. Studio enables this mode automatically when Tile sheets is the only
selected output.

The output grid is `auto` by default: Build 42 maps (`256x256` cells) export to
native `256x256` TMX cells and v41 maps to `300x300` cells. Build 42 maps cannot
be converted to `300x300`; asking for it is an error. Use
`--target-cell-size 256` to reproject a v41 map to native cells. A 256 export writes
`cellFormat="native-256"` on the `.pzw` `<world>` element, which is how WorldEd in
PZ_Mapping_Tools recognises a native 256x256 project; without it the project
would open as a legacy 300x300 world. WorldEd has no grid format for other
sizes, so the converter warns that such projects open as legacy-300. Internally, source tiles are
converted through world coordinates:

```text
worldX = sourceCellX * sourceCellSize + localX
targetCellX = worldX / targetCellSize
targetLocalX = worldX % targetCellSize
```

Exit codes: `0` success, `1` usage error or cancelled clean, `2` failure.
Large maps may need a bigger Java heap, for example `java -Xmx12g -jar ...`.
